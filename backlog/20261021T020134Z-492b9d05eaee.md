# Document peer memory and config link persistence

## Description

## Description
Record two accepted persistence risks in SECURITY.md. OpenCode maintenance follows configuration-file links by design, so a guarded session can redirect the next install's or update's permission write to another JSON object file. Peer runtime grants to ~/.claude/projects and ~/.grok/memory apply across the whole session and every project, and those stores carry instructions into later unguarded sessions.

## Scope / Surfaces Affected
SECURITY.md only. Out of scope: code changes, and the separate open question on Pi and OMP instruction persistence.

## Acceptance Criteria
SECURITY.md states both risks as accepted, with their limits: for configuration links, only bash and external_directory change, explicit denies are kept, and nothing is written when no change is needed; for peer grants, they are session-wide and cross-project and are available to the outer agent too.

## How to Verify
Read the changed sections against installer/harness/opencode.zsh and engine/peer-runtime.sb.
