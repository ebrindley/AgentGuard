# Publish final OpenCode Guard and pi-sandbox-guard releases and archive

## Description

Publish final releases of OpenCode Guard and pi-sandbox-guard that tell users where to go and how to recover, then archive each repository once its migration works. This step reaches both end states in docs/DESIGN.md section 12. It also settles what the Pi migration left for later: `~/.config/pi-sandbox-guard/` and the legacy bundle `state/legacy/pi-sandbox-guard/` (docs/DESIGN.md section 11, The Pi migration).

## Scope / Surfaces Affected

- OpenCode Guard: a final release whose `README.md` and release notes point to Agent Guard's one-line install and give recovery steps.
- pi-sandbox-guard: the same, as its last release note.
- The two OpenCode Guard Macs: check that OpenCode Guard's files are gone. The forwarders at the old command paths are removed by the first `update` after a restart since the switch (step 5), not by this step.
- `~/.config/pi-sandbox-guard/` and `state/legacy/pi-sandbox-guard/` on Macs migrated from pi-sandbox-guard, and the reinstate steps uninstall prints (D6).
- The launcher: remove the legacy nesting checks, `OPENCODE_SANDBOXED=1` (step 3) and `AGENT_GUARD_SANDBOXED=1` without a snapshot (step 9; docs/DESIGN.md section 7, Nested launch), once no session started before them can reach the launcher on either Mac.
- Archiving both GitHub repositories.
- Out of scope: new Agent Guard features and any change to OpenCode Guard or pi-sandbox-guard behavior.

## Acceptance Criteria

- Each final release names Agent Guard, the install command and what the migration changes. It also gives recovery for a failed or partial migration: where the permission record (OpenCode Guard) or the legacy bundle and `~/.config/pi-sandbox-guard/` (pi-sandbox-guard) are kept, and how to get back to a guarded start.
- The pi-sandbox-guard notes repeat the behavior change from docs/DESIGN.md section 11: an unguarded Pi now refuses tools instead of warning.
- Until this step, `~/.config/pi-sandbox-guard/` stays in place and unchanged, and the legacy bundle is kept (docs/DESIGN.md section 11). This step decides, records in docs/DESIGN.md section 11 and implements two things: what happens to `~/.config/pi-sandbox-guard/` (kept, removed, or moved into the legacy bundle) and when; and how long the legacy bundle is kept, given that uninstall copies it to `~/Agent Guard/pi-sandbox-guard-legacy/` and its reinstate steps name that copy.
- Whatever is decided, the steps uninstall prints and the pi-sandbox-guard release's recovery steps name only files that still exist at that point. Any removal is journaled and can be repeated, like the OpenCode Guard retirement.
- On both Macs, OpenCode Guard's engine, shims, forwarders, plugin, app, rulebook entry and PATH blocks are gone. `~/OpenCode Guard` (the old list, log and any permission backup) is kept, as OpenCode Guard's own uninstaller keeps it.
- OpenCode Guard is archived once both Macs have switched (step 6) and their forwarders are gone. pi-sandbox-guard is archived once Pi runs under Agent Guard on the owner's Mac and the conformance suite passes for both profiles (step 10d).
- End state check: both Macs run the Rust release, and Agent Guard's uninstall has been tested (docs/DESIGN.md section 12).
- After the legacy nesting checks are removed, `grep -rn OPENCODE_SANDBOXED engine plugin installer` finds nothing, a confined launch with `AGENT_GUARD_SANDBOXED=1` and no snapshot is refused, and the step 2 checks pass.

## How to Verify

- On each Mac, `~/Library/Application Support/OpenCodeGuard`, `~/Applications/OpenCode Guard.app`, `~/.config/opencode/plugins/opencode-guard.js` and `~/.cc-safety-net/rules/opencode-guard/` do not exist, and `~/OpenCode Guard` does. There are no `# >>> opencode-guard >>>` blocks in `.zprofile`, `.zshrc` or `.bash_profile`, and the `opencode-guard` entry in `~/.cc-safety-net/rules/rule.json` is gone.
- On each Mac, terminal launch, app launch and `agent-guard doctor` pass on the Rust release.
- On the owner's Mac, `~/.config/pi-sandbox-guard/` and `state/legacy/pi-sandbox-guard/` are in the state that docs/DESIGN.md section 11 records.
- Follow each release's recovery steps once in a disposable home and reach a guarded start. After a Pi migration there, uninstall and follow the printed steps: every file they name exists, and Pi starts under pi-sandbox-guard.
- GitHub shows both repositories as archived, with the final release as the latest.
