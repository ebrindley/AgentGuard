# Publish final OpenCode Guard and pi-sandbox-guard releases and archive

## Description

Publish final releases of OpenCode Guard and pi-sandbox-guard that tell users where to go and how to recover, then archive each repository once its migration works. This step reaches both end states in docs/DESIGN.md section 12.

## Scope / Surfaces Affected

- OpenCode Guard: a final release whose `README.md` and release notes point to Agent Guard's one-line install and give recovery steps.
- pi-sandbox-guard: the same, as its last release note.
- The two OpenCode Guard Macs: check that OpenCode Guard's files are gone. The forwarders at the old command paths are removed by the first `update` after a restart since the switch (step 5), not by this step.
- `engine/launch`: remove the legacy `OPENCODE_SANDBOXED=1` nesting check (step 3), once no OpenCode Guard session can reach the launcher on either Mac.
- Archiving both GitHub repositories.
- Out of scope: new Agent Guard features and any change to OpenCode Guard or pi-sandbox-guard behavior.

## Acceptance Criteria

- Each final release names Agent Guard, the install command and what the migration changes. It also gives recovery for a failed or partial migration: where the permission record and shim backups are kept, and how to get back to a guarded start.
- The pi-sandbox-guard notes repeat the behavior change from docs/DESIGN.md section 11: an unguarded Pi now refuses tools instead of warning.
- On both Macs, OpenCode Guard's engine, shims, forwarders, plugin, app, rulebook entry and PATH blocks are gone, and `~/OpenCode Guard` (the old list, log and any permission backup) is kept, as OpenCode Guard's own uninstaller keeps it.
- OpenCode Guard is archived once both Macs have switched (step 6) and their forwarders are gone. pi-sandbox-guard is archived once Pi runs under Agent Guard on the owner's Mac and the conformance suite passes for both profiles (step 10).
- End state check: both Macs run the Rust release, and Agent Guard's uninstall has been tested (docs/DESIGN.md section 12).
- After the legacy nesting check is removed, `grep -rn OPENCODE_SANDBOXED engine profiles` finds nothing and the step 2 checks pass.

## How to Verify

- On each Mac, `~/Library/Application Support/OpenCodeGuard`, `~/Applications/OpenCode Guard.app`, `~/.config/opencode/plugins/opencode-guard.js` and `~/.cc-safety-net/rules/opencode-guard/` do not exist, and `~/OpenCode Guard` does. There are no `# >>> opencode-guard >>>` blocks in `.zprofile`, `.zshrc` or `.bash_profile`, and the `opencode-guard` entry in `~/.cc-safety-net/rules/rule.json` is gone.
- On each Mac, terminal launch, app launch and `agent-guard doctor` pass on the Rust release.
- Follow each release's recovery steps once in a disposable home and reach a guarded start.
- GitHub shows both repositories as archived, with the final release as the latest.

## Dependencies

- Step 5 (OpenCode Guard migration): forwarder removal.
- Step 8 (Rust launcher)
- Step 10 (`@project`, then Pi and OMP)
