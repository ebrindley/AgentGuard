# Classify OpenCode service status in three states

## Description

## Scope / Surfaces Affected

- `profiles/opencode/runtime.zsh`: one classifier for `opencode service status` output (running, inactive, unknown) used by the incumbent check and the readiness wait in `opencode_managed`.
- `test/opencode-runtime.mjs`: offline classifier, incumbent and readiness cases.
- `test/opencode-v2-native.mjs`: the fake desktop connects to the launcher's server by address; new `gui-disabled` case with `disabled: true` in the service config.
- `docs/USAGE.md`, `SECURITY.md`, `docs/DEVELOPMENT.md`: 2.1.4 as tested, the service opt-out note, the new native case.

## Acceptance Criteria

- A single http or https URL is running; exactly `stopped` or `disabled` is inactive; anything else, including empty output or a failed probe, is unknown.
- The incumbent check continues on inactive, refuses running with the existing message, and refuses unknown with "unrecognized service status" without echoing arbitrary output.
- The readiness wait treats only running as ready and keeps polling through inactive and unknown until the existing limit, then fails with the existing message.
- The refusal points stay two; the recorded count is unchanged.
- Native `gui`, `gui-disabled`, `gui-signal`, `gui-server-stop`, `managed-cli` and `routing` pass on OpenCode 2.1.4.

## How to Verify

- `node test/opencode-runtime.mjs`
- `AG_TEST_OPENCODE=<opencode 2.1.4> node test/opencode-v2-native.mjs <case>` for each case above, outside any sandbox.
