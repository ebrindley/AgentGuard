# Move Pi and OMP to cc-safety-net

## Description

Pi and OMP use pi-sandbox-guard's analyzer, about 5,500 lines of bash and JavaScript maintained here, while OpenCode uses cc-safety-net. Move Pi and OMP to cc-safety-net with the checker policy of docs/DESIGN.md decision D13 and retire the analyzer (section 12, step 10d). Pi's confirmations end: each verdict is allow or deny (THREAT-MODEL.md section 8). Depends on the shared session-copy builder from "Apply the D13 checker policy to OpenCode".

## Scope / Surfaces Affected

- Pi's launch: build the session checker copy with the shared builder and pass it to the extension.
- The Pi extension: run cc-safety-net's Pi entry through a wrapper (stand-in Pi API, worst result across working folders) in place of the analyzer, with the settings of DESIGN.md section 5, Command checker.
- The analyzer, its interpreter binding (`.guard-node`, `--checker-node`) and its log: retired, in a separate release after the switch.
- `test/checker-comparison.mjs` and its fixture: regenerated against the new policy.
- Release notes: the confirmations removed and the commands newly refused or allowed.
- Out of scope: a new parser, private cc-safety-net exports or a vendor fork; changes to `~/.cc-safety-net`.

## Acceptance Criteria

- Pi and OMP sessions give D13's verdicts for every command group of docs/CHECKER-COMPARISON.md, with the gaps DESIGN.md section 5 records.
- cc-safety-net's Pi entry loads in OMP, in a disposable home.
- p50 and p95 latency per call and the count of 2-second timeouts are recorded.
- A missing session copy, a missing Agent Guard rulebook or a policy state other than `ready` blocks the call.
- The analyzer and its binding are gone from the release, and uninstall and update handle installs that still have them.

## How to Verify

- The comparison script reproduces the fixture.
- Real Pi and OMP sessions in a disposable home: a denied and an allowed command from each group.
