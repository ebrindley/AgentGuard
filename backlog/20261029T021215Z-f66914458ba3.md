# Peers keep policy files locked and Claude saves its state

## Description

Every guarded session grants the runtime folders of Claude, Codex, Cursor and Grok to peer commands (`engine/peer-runtime.sb`). Those grants name runtime state only, so the harnesses' policy files are write-protected by default; nothing asserts it. Claude also writes `~/.claude.json` through a temporary sibling when Poetic or a peer runs it inside a guarded session, and the grants do not cover either.

## Scope / Surfaces Affected

- `engine/peer-runtime.sb`: `~/.claude.json` and its temporary siblings.
- `test/peers.mjs`: Claude's settings and hooks, Codex's configuration and rules, Cursor's CLI configuration and Grok's locked files stay unwritable in OpenCode, Pi and OMP sessions; `~/.claude.json` and its siblings are writable.
- docs/DESIGN.md: one sentence in the peer section.
- Out of scope: project-level `.claude`, `.codex` and `.cursor` folders; Claude's `backups` folder.

## Acceptance Criteria

- No guarded session can write Claude's `settings.json`, `settings.local.json`, `hooks`, Codex's `config.toml`, `rules`, Cursor's `cli-config.json` or Grok's configuration, hooks and executables.
- A guarded session can write `~/.claude.json` and `~/.claude.json.tmp.<pid>.<hex>`, and nothing else beside them.
- OpenCode's golden profiles are unchanged unless the difference is recorded in `test/fixtures/differences`.

## How to Verify

Run `node test/golden.mjs` and `node test/peers.mjs` outside `/private/tmp`.
