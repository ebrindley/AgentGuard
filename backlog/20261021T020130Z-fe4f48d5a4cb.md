# Stop leftover OpenCode check servers

## Description

## Description
The OpenCode plugin check starts its server in the background, where a non-interactive shell ignores SIGINT, so an interrupted check leaves the server running on 127.0.0.1. Recovery in installer/lib.zsh only kills a recorded server whose command line contains 'serve --hostname 127.0.0.1', which the V1 check's command never matches, and the V2 check records no server at all. The leftover server stays confined but blocks the OpenCode Guard migration's process check until it is killed.

## Scope / Surfaces Affected
profiles/opencode/hooks.zsh (both check paths), ag_recover in installer/lib.zsh, and focused tests. Out of scope: the check's probes and results, and the managed V2 service lifecycle in profiles/opencode/runtime.zsh.

## Acceptance Criteria
A check interrupted by SIGINT, SIGTERM or SIGHUP stops its server and event reader and removes its files. Each check records its server with the owner's and server's start times. Recovery stops the server of a check that is no longer running, leaves a running check alone, removes leftover check files of checks that are no longer running, and still handles a .serve.pid left by an earlier release.

## How to Verify
Focused tests for the check interrupt and for recovery, plus the existing OpenCode health and install checks.
