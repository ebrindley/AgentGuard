# Refuse prefixed OpenCode attach in peer wrappers

## Description

## Description
engine/peers.zsh refuses OpenCode attachment only when the first argument is attach, so opencode --print-logs attach <url> runs from a peer wrapper. On V2 the shared argument parser sees the attach but calls note, which only the main launcher defines, and the wrapper ignores the result. SECURITY.md says peer attachments are refused.

## Scope / Surfaces Affected
engine/peers.zsh and test/peers.mjs. Out of scope: the main launcher's operator-selected attachment, which stays permitted, and profiles/opencode/runtime.zsh.

## Acceptance Criteria
Peer wrappers refuse attach after leading --print-logs and --log-level options for V1 and V2 with the existing must-execute-locally message and exit status 2. Other peer commands and the main launcher's attach handling are unchanged.

## How to Verify
node test/peers.mjs.
