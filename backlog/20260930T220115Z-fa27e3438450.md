# Replace the zsh launcher with a Rust binary delivered as an update

## Description

Replace the zsh launcher with a Rust binary that behaves the same and ship it as an ordinary `update`, after both Macs already run Agent Guard, so rewrite failures stay separate from migration failures. A Mac where the binary cannot run keeps the zsh version.

## Scope / Surfaces Affected

- New Rust crate: launcher, list parser, profile builder, the OpenCode profile as embedded TOML with the same fields as the zsh profile (docs/DESIGN.md section 3) and Rust versions of the `opencode_prepare` and `opencode_check` hooks.
- `Cargo.lock` (committed) and one `cargo deny` configuration.
- Release packaging: a universal binary (arm64 and x86_64) with an ad-hoc signature on each slice.
- The step 2 engine adapter, pointed at the Rust engine; a test-only home injection that release builds do not contain.
- The installer's `update` path: run the staged binary before switching.
- docs/DESIGN.md section 7 and `README.md`: minimum macOS version, admission and rollback.
- Out of scope: Linux and Windows, Developer ID signing and notarization (open in docs/DESIGN.md section 15), per-launch state files (step 9), `@project` and the Pi profile (step 10).

## Acceptance Criteria

- Seatbelt code is in one module. `unsafe` appears only in one small FFI module and is rejected by a lint everywhere else.
- Each crate beyond the standard library is justified in the pull request. `cargo deny check` is the only dependency advisory check.
- The golden test passes unchanged against the Rust engine: on both golden lists it writes the same profile bytes as the zsh engine at the same release, which is the v1.0.3 fixtures plus the recorded differences of steps 5 and 7.
- `agent-guard doctor` runs from the Rust binary with the same checks as the zsh version, including step 7's plugin check.
- The step 2 behavioral checks pass unchanged against the Rust engine. Where they do not yet cover argument forwarding, executable selection, environment cleanup, exit status and signals, checks are added and run against both engines first.
- The launcher skips every guard shim, old and new (docs/DESIGN.md section 10, rule 8), and takes home from the account database, not `$HOME`.
- The test-only home injection is compiled only into test builds, and the release build is checked for its absence (docs/DESIGN.md section 8). The golden test's spoofed-environment check passes against the release artifact.
- The binary, every shim and every symlink that launches it are write-protected against replacement and ancestor renames.
- `lipo -archs` reports `arm64 x86_64`, and each slice passes signature verification after packaging.
- The minimum macOS version is stated in `README.md` and set in the build. When `update` runs on an older macOS, it refuses to switch.
- When the staged binary cannot run (blocked by Santa or Gatekeeper, wrong architecture, older macOS or a failed self-test), `update` exits non-zero before switching and the zsh version still launches.
- The work Mac's route for admitting a new binary, collected at step 6, is settled before this update runs there.
- The zsh engine stays in the repository until both Macs run the Rust version. After that the last zsh release stays published, and installing it over the Rust version is tested as the rollback.

## How to Verify

- `cargo deny check` passes, and a search for `unsafe` matches only the FFI module.
- Run the golden test and the integration checks through the engine adapter, once for each engine. Both pass, and the profile bytes match.
- `lipo -archs <binary>`, then `codesign --verify --verbose --arch arm64 <binary>` and the same with `--arch x86_64`. Both report a valid signature.
- `otool -l <binary>` shows the stated minimum in `LC_BUILD_VERSION`.
- In a disposable home, run `update` with a staged binary that cannot run. It exits non-zero, and the zsh launcher still starts OpenCode guarded.
- On each Mac after `update`: terminal launch, app launch and `doctor` pass. Then install the last zsh release over it and repeat the same checks.
