# Deny the microphone to the guarded desktop

## Description

A prompt "'Agent Guard' would like to access the Microphone" appears when OpenCode Desktop plays its "agent finished" sound (observed 2026-10-24 and 2026-10-25). Desktop 2.1.4 has no audio capture, but its helpers carry `com.apple.security.device.audio-input`. On 2026-10-25 the request came from `coreaudiod` as the audio helper opened the default output, Jump Desktop Audio, which has 8 input and 8 output channels; tccd named Agent Guard.app as the responsible process. A Seatbelt `(deny device-microphone)` rule had no effect, because `coreaudiod` makes the request outside the sandbox. With the hardened runtime, tccd refuses a microphone prompt when the responsible app lacks the audio-input entitlement (OrbStack #2546, cmux #1325).

## Scope / Surfaces Affected

- `installer/lib.zsh`: sign Agent Guard.app with `--options runtime` and `profiles/opencode/assets/AgentGuard.entitlements`, which holds every hardened-runtime resource-access entitlement except audio input; add the signing options and the entitlements to the app's rebuild inputs; fail when the entitlements file is missing.
- `scripts/release.sh`: package the entitlements file.
- `test/install.sh`: the installed app's runtime flag and entitlements; the rebuild decision.
- SECURITY.md, docs/DESIGN.md, docs/THREAT-MODEL.md, docs/USAGE.md (microphone bullet).
- Out of scope: Seatbelt profile rules, other privacy services, CLI mode.

## Acceptance Criteria

- The installed app has the hardened runtime and exactly the six entitlements: Apple Events, camera, contacts, calendars, location, photos library.
- A change to the signing options or the entitlements rebuilds an existing app; identical inputs keep it; a missing entitlements file stops the install.
- With OpenCode Desktop started fresh through Agent Guard.app and Jump Desktop Audio as the default output, an agent reply's sound plays on that device, no microphone prompt appears, and tccd logs the hardened-runtime refusal for the app.
- The docs state the behavior, the recorded failure, the scope (processes the app starts) and the cost.

## How to Verify

- `test/install.sh` passes.
- The real-app check in the acceptance criteria.
- The hosted `tests` check passes.
