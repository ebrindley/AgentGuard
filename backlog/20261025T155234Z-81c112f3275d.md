# Deny the microphone to the guarded desktop

## Description

On 2026-10-24 a prompt "'Agent Guard' would like to access the Microphone" appeared 155 ms after OpenCode Desktop played its "agent finished" sound. OpenCode's app and helpers carry `com.apple.security.device.audio-input`, and Desktop 2.1.4 has no audio capture. Agent Guard.app is the responsible process, so the prompt names it, and its ad hoc signature means a rebuild makes macOS ask again. Apple's App Sandbox gates microphone access with the `device-microphone` operation (`appsandbox-common.sb`, `audio-input`), separately from audio output.

## Scope / Surfaces Affected

- `engine/profile.sb`: deny `device-microphone` when `GUI=1`, beside the authorization-service deny, kept after every allow.
- The golden profile record (`test/fixtures/differences/`), as for the authorization-service deny.
- SECURITY.md, docs/DESIGN.md (rule order), docs/THREAT-MODEL.md, docs/USAGE.md (microphone bullet).
- Out of scope: camera, CLI mode, other Mach services or operations, the applet's signing.

## Acceptance Criteria

- The `GUI=1` profile denies `device-microphone`; the `GUI=0` profile does not.
- No earlier rule, including list rules and peer runtime grants, can allow it again.
- With OpenCode Desktop opened through Agent Guard on the output device that raised the prompt, an agent reply's sound plays and no microphone prompt appears.
- The docs state the rule, the recorded failure, and that a future OpenCode microphone feature would not work under the guard.

## How to Verify

- The golden test and the focused profile tests pass.
- A real-app check on the affected device, as in the acceptance criteria.
- The hosted `tests` check passes.
