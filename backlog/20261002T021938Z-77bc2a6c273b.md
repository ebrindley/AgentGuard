# Name OpenCode's bin and model catalog in the 0.1.1 limitations

## Description

`SECURITY.md` and `README.md` say only OpenCode's package store is writable inside the guard. In 0.1.1 all of `~/.cache` is writable (`profiles/opencode/harness.zsh`), which also covers two other parts of `~/.cache/opencode` that OpenCode 1.18.34 runs or trusts: `bin`, where it keeps and runs downloaded ripgrep and language servers (`packages/core/src/global.ts`), and the model catalog `models.json` or `models-<hash>.json`, which sets each provider's API address and package (`packages/core/src/models-dev.ts`). Name all three in the known limitation until step 7 protects them.

## Scope / Surfaces Affected

- `SECURITY.md`: the boundary summary and the first item of Known limitations in 0.1.1.
- `README.md`: Limitations.
- Out of scope: protecting these paths (step 7); docs/DESIGN.md, which already describes them (section 9).

## Acceptance Criteria

- `SECURITY.md` and `README.md` name the package store, `bin` and the model catalog as writable in 0.1.1, with what an agent can do with each: plugin code imported at the next start, binaries OpenCode runs, and a catalog that can send a provider's API key to another host or load a package.
- The text says step 7 protects all three.
- No other behavior is described as changed.

## How to Verify

- `grep -n "bin\|catalog" SECURITY.md README.md` shows the new text in Known limitations and Limitations.
- The claims match `profiles/opencode/harness.zsh` and docs/DESIGN.md section 9.
