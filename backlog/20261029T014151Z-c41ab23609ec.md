# Grok CLI harness on the zsh engine

## Description

Add Grok CLI as a harness on the zsh engine, ahead of the Rust launcher. Grok's built-in sandbox profiles block the macOS keychain, so gh and git over https fail inside them. Agent Guard owns Grok's boundary instead and runs Grok with `--sandbox off`. Section 1 of docs/DESIGN.md excludes harnesses that ship their own sandbox, and section 7 says the zsh engine is not extended; this is a recorded exception to both.

## Scope / Surfaces Affected

- `engine/launch` takes the harness it launches; OpenCode's generated profiles stay byte-identical.
- `profiles/grok/`: harness data, launch arguments, shim.
- `engine/peers.zsh`: Grok found through its recorded executable and launched with the same arguments.
- `installer/harness/grok.zsh` and the registry: shim at `~/.local/bin/grok`, recorded executable, uninstall, doctor.
- docs/DESIGN.md, docs/USAGE.md, docs/OPERATIONS.md, release file list, tests.
- Out of scope: Rust launcher, Grok plugin adapter, project-level Grok hook configs, Grok Desktop.

## Acceptance Criteria

- Plain and scripted `grok` launches reach the guard and run with `--sandbox off`, local execution and the updater off.
- An explicit non-off `--sandbox`, `--leader`, a relocated `GROK_HOME` and a resume of a natively sandboxed session are refused with a message.
- Inside another sandbox the launcher steps aside but keeps the same arguments.
- Grok's configuration, hooks, binaries and the shim are not writable; skills, plugins, AGENTS.md, memory and sessions are.
- The credential set is denied for read and write; `~/.config/gh` is readable and not writable.
- `agent-guard doctor` reports which `grok` wins for interactive and `zsh -c` lookups.
- `test/golden.mjs` passes unchanged.

## How to Verify

Run `node test/golden.mjs`, `node test/grok.mjs`, `zsh test/grok-install.sh` and `zsh test/test.sh` outside `/private/tmp`; uninstall leaves `~/.local/bin/grok` as it was.
