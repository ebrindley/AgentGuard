# Record credentials, hooks and composed nesting for every harness

## Description

Record the reviewed design in docs/DESIGN.md and the backlog: credentials and Git hook protection apply to every harness, inference credentials get their own class, a nested launch runs under a session built to include it, and runtime data that runs code is protected before Pi ships and before composition. Documentation and backlog only.

## Scope / Surfaces Affected

- docs/DESIGN.md: the status line and sections 2, 3, 5, 7, 8, 9, 11, 12, 14 and 15.
- Backlog: the step 7 and step 10 items; a new item for OpenCode's releases after Pi; three captured items (the SSH agent socket, persistent-instruction folders, Pi's login storage).
- Out of scope: code, tests, the installer and the installed Macs.

## Acceptance Criteria

- Decisions D2 and D3 are replaced. The `credentials` and `hooks` profile fields are removed; `nested` keeps `inherit` only for OpenCode's transition.
- The credential set has a tool class and an inference class, and every credential exception is cut out of the deny it narrows. OMP's `.env` files are checked at launch.
- Git hooks protection covers every harness, including the selector unsets, R8's `XDG_CONFIG_HOME`, OMP worktrees under granted roots, OpenCode's `core.hooksPath` block and the app after step 10a.
- Composition defines presence, the combined executable check, grants, protections, snapshot members, the nested rule, start dates and the accepted cost.
- Step 7 covers OpenCode's `bin` folder and model catalog, and from step 10c every launch renders every installed harness's denies inside granted folders. The remaining code-loading items gate composition.
- The release order, acceptance tests, section 8 cases and section 14 wording match.
- No tracked file names a person, a host name or an account home path.
