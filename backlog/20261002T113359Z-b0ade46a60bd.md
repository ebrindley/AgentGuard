# Add agent-guard bind, wrapper and Pi doctor checks

## Description

The commands that replace pi-sandbox-guard's npm scripts, at the paths the adopted layout keeps: `agent-guard bind`, `agent-guard wrapper add|remove|list`, and the Pi checks of `doctor` and `doctor --json`.

## Scope / Surfaces Affected

- `agent-guard bind`: pi-sandbox-guard's `bind-executable.sh` behavior, writing `~/.config/pi-sandbox-guard/executables.conf`, plus `--checker-node` for the extension's `.guard-node`.
- `agent-guard wrapper add|remove|list`: pi-sandbox-guard's wrapper validation, copies in `~/.local/bin`, records in `$engine/state/wrappers.json` with historical names and hashes; reserved names `pi`, `omp`, `opencode`, `opencode-gui`, `agent-guard`.
- `doctor` Pi checks: installed file hashes against the release, entry-point resolution, bindings and `.guard-node` staleness, wrapper hashes and historical names, the profile self-test, the analyzer preflight with one allowed and one blocked command, and `pi --version` and `omp --version` from a scratch project. `doctor --json` keeps `status --json`'s fields.
- Out of scope: installing these files (Pi install item).

## Acceptance Criteria

- Each command behaves as pi-sandbox-guard's script did for the same inputs, apart from the recorded changes.
- A missing runtime is skipped and named; a stale binding fails.
- `doctor --json` has `runtime_binding`, `pi_binding`, paths and drift with `status --json`'s semantics.

## How to Verify

- Unit tests with a disposable home for each command.

## Dependencies

- Adopt pi-sandbox-guard's Pi profile (file layout).
