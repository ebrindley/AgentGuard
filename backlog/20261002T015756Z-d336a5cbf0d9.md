# Decide whether to protect persistent-instruction folders

## Description

Two runtime folders let an agent leave instructions that later sessions load, and the planned Pi profile leaves both writable from sessions:

- Pi's prompt templates in `<agent-dir>/prompts/` (`~/.pi/agent/prompts` by default) become `/` commands whose text enters the agent when invoked (Pi 0.99.2 documentation, `docs/prompt-templates.md`). Pi's grant is its whole root, and `state_config` covers templates only through the `*prompt*.md` name, so `prompts/review.md` is writable.
- OMP's `memories` folder is in OMP's `state_grants`. With the `local` memory backend, OMP injects the project's `memory_summary.md` and captured lessons from it into the instructions of later sessions in that project (OMP 18.4.9 `packages/coding-agent/src/memories/index.ts`).

Also found: Pi 0.99.2 applies user instructions from `AGENTS.override.md`, `AGENTS.md`, `AGENTS.MD`, `CLAUDE.md` or `CLAUDE.MD` in its agent folder to every working directory (`docs/configuration.md`, Agent directory). None of these is in Pi's `state_config`; OMP's agent-folder `AGENTS.md` is in OMP's.

Decide for each whether to protect it or accept it in writing (docs/DESIGN.md section 15, open decisions).

## Scope / Surfaces Affected

- `[state_config.pi_agent]` and `[state_grants.omp_agent]` in `engine/profiles/pi.toml` (docs/DESIGN.md section 3, Planned Pi profile), and the plugin projection.
- docs/DESIGN.md sections 3 and 15; the Pi release notes.
- Out of scope: instruction files inside a project, which sit in ALLOW folders the agent edits (docs/DESIGN.md section 1, non-goals); a project's `.pi/prompts`, which the `.pi` name rule already covers.

## Acceptance Criteria

- docs/DESIGN.md records protect or accept for Pi's `prompts/`, Pi's agent-folder instruction files and OMP's `memories`, each with its cost. Protecting `memories` stops OMP's memory pipeline from updating inside the guard, because OMP writes it during sessions. Protecting Pi's templates and instruction files stops edits made from inside a session, including asking Pi to make them.
- A protected item is write-denied at every root level, including creation, rename and symlink replacement, with a conformance case.
- An accepted item is listed with its reason in docs/DESIGN.md section 15 and in the Pi release notes.

## How to Verify

- Inside a guarded Pi session, write `~/.pi/agent/prompts/x.md` and `~/.pi/agent/AGENTS.md`; inside a guarded OMP session, write a file under the agent folder's `memories/`. Each result matches the recorded decision.

## Dependencies

- Step 10d (the Pi profile); a decision to protect lands with it or in a later release.
