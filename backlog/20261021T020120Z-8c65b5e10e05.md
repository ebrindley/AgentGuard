# Fix the Codex peer database write grant

## Description

## Description
The Codex peer grant for versioned databases in engine/peer-runtime.sb spells its regex with a doubled backslash, which SBPL reads as a literal backslash, so it matches no real file. Codex 0.163.0 keeps state_5.sqlite, logs_2.sqlite, queue_1.sqlite and thread_history_1.sqlite (with -wal and -shm files) directly in ~/.codex, and guarded sessions deny those writes. Correcting only the backslash would also grant memories_1.sqlite and goals_1.sqlite, and would match the names in subfolders.

## Scope / Surfaces Affected
engine/peer-runtime.sb, the pinned peer-runtime text in test/fixtures/differences/step-8.json, and the peer runtime write checks in test/peers.mjs. Out of scope: other peer grants and SECURITY.md wording.

## Acceptance Criteria
Guarded OpenCode, Pi and OMP sessions can write the state, logs, queue and thread_history databases and their -wal and -shm files directly in ~/.codex. memories_1.sqlite, goals_1.sqlite and the same database names in a subfolder of ~/.codex stay write-denied.

## How to Verify
node test/golden.mjs and node test/peers.mjs.
