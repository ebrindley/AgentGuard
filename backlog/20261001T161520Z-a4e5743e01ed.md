# Test the migration from every OpenCode Guard release

## Description

## Description

The migration tests install OpenCode Guard v1.0.3 and v1.0.4 with each tag's own installer. The two existing installs may run any release from v1.0.0 to v1.0.4, possibly upgraded in place over an older one. Add real installs of v1.0.0 and v1.0.1, so that the tests cover the inputs of every release, and correct three statements in docs/DESIGN.md.

## Scope / Surfaces Affected

- `test/fixtures/installs/opencode-guard-1.0.0` and `opencode-guard-1.0.1`: unmodified `git archive` trees of the tags with the same paths as the existing fixtures, and their rows in the fixtures README.
- `test/migrate.sh`:
  - setup, M1 and the uninstall, M9 and M5 loops run for v1.0.4, v1.0.3, v1.0.1 and v1.0.0;
  - each M1 also runs the entry-point probe;
  - for each new version, one late rollback (`fail:doctor-live`) that leaves OpenCode Guard's files byte-identical;
  - one v1.0.0 `kill:fwd-gui`, with the probe and a rerun;
  - one v1.0.0 install upgraded in place by v1.0.4's installer, then migrated and uninstalled.
- `docs/DESIGN.md`:
  - OpenCode Guard adds `env` to `transparent_wrappers` from v1.0.2, not v1.0.1;
  - M6 does not include a reinstall;
  - the Tests and Recovery testing paragraphs name the four fixtures and say why v1.0.2 needs none: its `install.sh` equals v1.0.3's, and its list template equals v1.0.1's.
- Not in scope:
  - the full fail and kill matrices on the older versions, which stay on v1.0.4;
  - partial OpenCode Guard installs;
  - installer changes.

## Acceptance Criteria

- `zsh test/migrate.sh` passes with 0 failures on macOS 26. Each of the four versions migrates, uninstalls and reinstalls.
- In the upgrade case, the record keeps v1.0.0's `orig` values, the list keeps v1.0.0's template, and uninstall restores the pre-guard values.
- CI passes on the pull request.

## How to Verify

- `zsh test/migrate.sh`, run outside any sandbox.
- The CI run on the pull request.
