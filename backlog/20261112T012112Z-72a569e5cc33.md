# Fix the Desktop check for a missing claude

## Description

## Scope / Surfaces Affected

`profiles/opencode/browser/gui.cjs` checks for a `claude` executable on `PATH`
before starting Claude Code sign-in from guarded Desktop, and reports "The
claude command was not found" when there is none. The launcher always puts its
`peers` folder first on `PATH`, and that folder holds a `claude` wrapper, so the
check always passes. Without Claude Code installed the wrapper exits 127 and
Desktop shows the older "exited before completing sign-in" message.
`test/browser.mjs` passes because its `PATH` has no `peers` folder.

The wrapper searches `AGENT_GUARD_PEER_PATH` and a list of fallback folders in
`engine/peers.zsh`. Either make the check use the same search, or remove the
check and its test case.

## Acceptance Criteria

- [ ] Given guarded Desktop on a Mac without Claude Code, when Claude Code sign-in starts, then the message says the command was not found, or the check and its message are removed.
- [ ] Given Claude Code installed in any folder the wrapper searches, sign-in starts as it does now.

## How to Verify

- `node test/browser.mjs` must pass with the launcher's `peers` folder first on `PATH` in the missing-command case.
