# Enable guarded browser handoff

## Description

## Scope / Surfaces Affected
Add a restricted browser handoff owned by the OpenCode launcher, a provider connection action using existing OpenCode APIs, and CLI browser forwarding for provider login. Preserve the sandbox Launch Services denial and vendor application files. Include packaging, lifecycle, focused tests and usage documentation.

## Acceptance Criteria
Browser invocation works through the restricted helper for ChatGPT, OpenCode and Claude authentication URLs. A visible OpenCode action invokes the supported provider flow without rewriting OAuth. Claude's separate login ownership remains explicit. File URLs, custom schemes and unrelated destinations cannot request application execution. Full account authentication is not required for this task.

## How to Verify
Use Node 24 and focused offline/helper tests, real Seatbelt caller probes, installed OpenCode GUI plugin compatibility where practical, and a harmless real browser-opening smoke test. Run one implementation pass and one corrective pass; stop and report if integration remains blocked. No live credential exchange required.
