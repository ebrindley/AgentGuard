# Run OpenCode inside another sandbox

## Description

## Scope / Surfaces Affected

`engine/launch` nested-sandbox branch; tests in the hosted gate (`test/opencode-runtime.mjs`, `test/pi-launch.mjs`); `docs/USAGE.md`, `SECURITY.md`, `docs/DESIGN.md` section 15 (D10), `docs/THREAT-MODEL.md`.

## Acceptance Criteria

- When the launcher starts inside a sandbox it did not create (no engine marker, and the nesting probe fails with `sandbox_apply: Operation not permitted`), `launch cli` runs the real OpenCode CLI with the V2 `--standalone` injection, refuses managed commands, prints one note to stderr, and writes no launch log, state or rules.
- The engine marker is not set in that case.
- `gui`, `check` and `profile` are refused with a message naming the other sandbox.
- Any other probe failure keeps today's behavior and does not run the CLI.
- Engine-marker nested behavior is unchanged.

## How to Verify

Run `node test/opencode-runtime.mjs` and `node test/pi-launch.mjs` outside any sandbox on macOS.
