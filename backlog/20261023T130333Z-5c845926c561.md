# Add a tracked landing route and PR subject check

## Description

`docs/DEVELOPMENT.md` states the landing rule: squash subject `<PR title>
(#<number>)`, body blank. Nothing applies it, so the subject and body are
composed by hand at each merge and two commits landed with bodies the rule says
should be blank.

The rule is mechanical, so it can live in a tracked script that every machine
gets through git. `.git/hooks` is not versioned and `core.hooksPath` is local
per-clone configuration, so a hook would need a manual step on each machine.

A shared check holds the subject rule once. A landing script applies it and
merges with an explicitly empty body, which removes the step where a body gets
composed. The PR gate runs the same check on the title, since the title becomes
the subject and does not exist locally.

The writing rules that govern what a message says rather than its shape stay
editorial. No check judges them.

## Scope / Surfaces Affected

- `script/check-subject`: new. The subject rule, used by both callers.
- `script/land`: new. Reads the PR title, checks the subject, merges with a
  blank body at the reviewed head.
- `.github/workflows/test.yml`: add the `edited` trigger type so a retitled PR
  rechecks, and a step running the check with the title passed as environment
  data.
- `docs/DEVELOPMENT.md`: name the landing route beside the rule it applies.

## Non-goals

- No commit-message linting over a branch range. The squash message is not any
  of those commits, and the range does not resolve in a depth-1 pull-request
  checkout.
- No push-triggered backstop. `full.yml` ignores Markdown and backlog paths,
  which is where the recorded failure landed.
- No rejected-word list. It blocks legitimate subjects and misses the phrasing
  it targets.
- No new required check, hook or per-machine setup.

## Acceptance Criteria

- [ ] A title whose subject with the ` (#<number>)` suffix reaches 72 characters
      is rejected, and one below it is accepted.
- [ ] A title ending in a period is rejected; the closing parenthesis of the
      suffix is not treated as a trailing period.
- [ ] An empty title and a non-numeric PR number are rejected.
- [ ] `script/land` merges with an empty body and against the reviewed head
      commit, and prints the subject before merging.
- [ ] Editing a pull request title reruns the gate.
- [ ] The gate step does not run for `workflow_dispatch`, which carries no pull
      request payload.
- [ ] A pull request title is never interpolated into a shell command.

## How to Verify

```bash
script/check-subject "Add a tracked landing route and PR subject check" 123
script/check-subject "A title that runs well past the limit so the suffix pushes it over" 1234
script/check-subject "Ends in a period." 1
script/test
```

The first must exit 0, the next three non-zero with the reason named. `script/test`
must still pass, since the new scripts are not part of its scope. `script/land`
is verified by landing this change with it.
