# Narrow the skill carve-out away from `.cc-safety-net`

## Description

The OpenCode profile's `.cc-safety-net` write deny carries
`(require-not (skill-content))`, and skill content matches any
`.opencode/skills?/<name>` path. A session can therefore create a
`.cc-safety-net` directory inside a skill tree, while the same create elsewhere
in the project is denied. DESIGN.md section 5 states that a session cannot write
a project `.cc-safety-net/policy.json`.

The gap sits in the layer that covers destructive commands inside granted
folders and local and remote history changes, where the Seatbelt profile
provides no containment by design, so nothing stands underneath it.
`CC_SAFETY_NET_PROJECT_TIGHTEN_ONLY=1` stops a project policy weakening a
verdict, which holds the current effect to a stale claim and a narrow hardening
gap rather than a checker bypass.

## Scope / Surfaces Affected

- `profiles/opencode/protected.sb`: the `.cc-safety-net` rule.
- `test/fixtures/differences/configuration.json`: the recorded `after` string
  reproduces that rule byte for byte, so it changes with it.
- DESIGN.md section 5, if the claim is corrected rather than the rule.

## Non-goals

- Not changing skill-content handling for any other path.
- Not changing `CC_SAFETY_NET_PROJECT_TIGHTEN_ONLY`.
- Not adding a checker or a new guardrail; this narrows an existing rule.

## Acceptance Criteria

- [ ] A `.cc-safety-net` path component is write-denied inside a skill tree, as
      it is elsewhere in a project.
- [ ] Skill content that does not contain a `.cc-safety-net` component stays
      writable wherever the carve-out permits it today.
- [ ] The recorded configuration-step difference matches the emitted rule byte
      for byte.
- [ ] DESIGN.md's statement about a project `.cc-safety-net/policy.json` matches
      behaviour.

## How to Verify

```bash
node test/golden.mjs
zsh test/test.sh
```

`test/golden.mjs` must report all of its checks passing, including the recorded
empty, nested and pi-installed profiles, which fail until the configuration-step
difference is updated to match the new rule. It must run outside any enclosing
sandbox; its account lookup fails otherwise. `test/test.sh` needs a real
OpenCode CLI ahead of the Guard shim on PATH, or `AG_TEST_OPENCODE` naming one,
and must show no new failures against a run from an unmodified checkout via
`--source`.

A direct check under `sandbox-exec` should show a `.cc-safety-net` create
refused both inside a skill tree and elsewhere in the project, and ordinary
skill content still writable.
