# Publish the first public release and switch the two existing Macs

## Description

Make the repository public with its contribution and security policy, publish the first release (OpenCode only), and switch the two existing OpenCode Guard installs, a home Mac and a work Mac, to it. The home Mac switches first; the work Mac switches only after the home Mac passes every check.

## Scope / Surfaces Affected

- **Facts before a switch.** The installer checks what the switch depends on before it changes anything, and stops with nothing changed or rolls back: the tools, the OpenCode Guard install it finds (v1.0.0 or later; `test/migrate.sh` migrates real v1.0.0, v1.0.1, v1.0.3 and v1.0.4 installs, each made by that release's own installer, and v1.0.0 upgraded to v1.0.4; v1.0.2's installer is v1.0.3's), running OpenCode processes, and the staged release against the Mac's own OpenCode. No separate fact collection runs. One fact it cannot check:
  - Work Mac only: whether Santa or another allowlisting tool runs (`santactl status`, including its mode), how a new binary is admitted there, and whether an ad-hoc signed app built on the Mac is admitted. The zsh engine runs through Apple-signed `/bin/zsh` and needs no admission (docs/DESIGN.md section 6). The app does: the installer builds it with `osacompile` and re-signs it ad hoc (`codesign --force --sign -`), so Santa would see it as a new binary. The installer's checks launch OpenCode from the terminal, not through the app.
  - Record only these facts. No hostnames, account names, serial numbers or employer details: backlog items can become public.
- **History review**, before the visibility change. Covers every ref on GitHub: `main`, `feat/opencode-stage-one`, `spike/opencode-plugin-cache`, `refs/pull/1/head`, `refs/pull/2/head`; PR #1 and #2 titles, bodies and comments; commit messages and author and committer identities; every file in every commit, including deleted ones.
  - Observed while writing this item: the two backlog items added in 2cd6cba and later removed from the tree (e64021c, 5424c15) remain in history. The spike item's text names local scratch evidence paths. Outside the `dscl` lookup in `engine/launch` (`/Users/$login`), no home path with an account name and no hostname was found. The two branches each hold one pre-squash commit (1b21aac, 8b0d161) that is not on `main`.
  - A rewrite and force-push does not remove commits reachable from PR refs; GitHub marks `refs/pull/*` read-only, and removing them needs GitHub Support ("Removing sensitive data from a repository", GitHub Docs). The other remedy is publishing from a new repository with clean history.
  - Findings, 2026-10-01, from a mirror clone: 14 refs (`main`, the two branches, `refs/pull/1/head` to `refs/pull/11/head`), 43 commits, 226 blobs, PRs #1 to #11 with their comments; PR #12 (96c8e07), merged after the review, adds only the public files. Author and committer identities are GitHub noreply addresses only. No credential, personal name, employer or `/Users/<name>` path in any blob, commit message or PR text; the credential-pattern hits are cc-safety-net's own detection patterns. History only: the spike item, added in 8b0d161 and 82f1ca8 and removed in 5424c15, names the development Mac's default mDNS host name, which gives the hardware model and no person, and two temporary scratch paths. Every `refs/pull/*/head` holds pre-squash commits that are not on `main`; their only other hits are older copies of docs/DESIGN.md with the same text as `main`. Current files say "home Mac" and "work Mac" and name Santa, with no employer.
  - Recommendation: publish as is. A rewrite would leave the host name in `refs/pull/2/head` to `refs/pull/11/head` unless GitHub Support purges them.
  - Decision: published as is, 2026-10-01. Pull requests: `collaborators_only`; visibility: public; private vulnerability reporting: enabled (`gh api` readback).
- **Public files.** New: `CONTRIBUTING.md`, `SECURITY.md`, `.github/CODEOWNERS`, `.github/ISSUE_TEMPLATE/config.yml`, `.github/ISSUE_TEMPLATE/bug_report.yml`, modeled on pi-sandbox-guard's files of the same names. Changed: `README.md`, which replaces the stage 1 text (including "do not use it to replace an existing OpenCode Guard installation before stage 2") with the one-liner, `update`, `uninstall`, recovery and limitations.
- **GitHub settings.** Settings > General > Features > Pull requests: "Collaborators only". This works on private repositories, so set it first. Visibility: public. Private vulnerability reporting: on. GitHub offers it only for public repositories, so switch it on right after the visibility change, before the release is used on either Mac.
- **Release.** The first tag and GitHub release: the complete release archive and its checksum in the step 4 format, and release notes. The version number is chosen here and matches the version stamp.
  - Published 2026-10-01: `v0.1.0` at b97064e, with `agent-guard-0.1.0.tar.gz`, `agent-guard-0.1.0.tar.gz.sha256` and `install.sh`. The suites passed on b97064e: golden 3, test.sh 163, release.sh 170, bootstrap.sh 34, install.sh 405 and migrate.sh 471 checks, 0 failures. The assets downloaded anonymously through `releases/latest/download/install.sh` and `releases/download/v0.1.0/` are byte-identical to the build, and the checksum matches.
  - Published 2026-10-01: `v0.1.1` at 9b7d1e5, before either Mac was switched. It fixes uninstall for an interrupted OpenCode Guard install: a permission key with no recorded written value is now left as is instead of getting its original value back (#14). It also adds the v1.0.0 and v1.0.1 migration tests (#15). CI on 9b7d1e5 passed every suite on macos-15 and macos-26 (migrate.sh runs on macos-26 only), with 0 failures: install.sh ran 407 checks and migrate.sh 586. The assets downloaded through `releases/latest/download/` are byte-identical to the build, and the checksum matches. The Macs switch to v0.1.1.
- **The two Macs.** The home Mac, then the work Mac, through the published one-liner, with terminal, app, `doctor` and recovery checks.
- Out of scope: Pi; package-store protection (step 7); the Rust launcher (step 8); final OpenCode Guard and pi-sandbox-guard releases and archiving (step 11); running `uninstall` on either Mac (end state, docs/DESIGN.md section 12); a DMG, a Homebrew cask, signing and notarization (docs/DESIGN.md section 6).

## Acceptance Criteria

History and settings:
- The history review's findings and decision (publish as is, rewrite with Support, or new repository) are recorded in this item before the visibility changes.
- After the visibility change, the PR setting reads "Collaborators only" and private vulnerability reporting is enabled. The `SECURITY.md` link opens a report form.

Public files (docs/DESIGN.md section 13):
- `CONTRIBUTING.md`: issues are welcome; external pull requests are not accepted, with the reason (a single maintainer on a security-sensitive tool) and the alternatives (open an issue, or fork under the MIT license). Bug-report guidance: reproduction steps, expected and actual behavior, macOS version and chip, harness and its version, Agent Guard version, launch route (terminal or app) and `doctor` output. It states the line between a bug and a vulnerability and sends vulnerabilities to `SECURITY.md`. None of this is in `AGENTS.md`.
- `SECURITY.md`: the private advisory form (`https://github.com/ebrindley/AgentGuard/security/advisories/new`) is the only private channel, and no email address is published. When the form is missing, the reporter opens a public issue with no exploit detail asking for a private channel. Best effort, no bounty. It states what the project is (a Seatbelt write-containment boundary; the plugin and cc-safety-net are advisory), what it does not cover (network, read confidentiality beyond DENY, integrity of ALLOW folders) and which versions get fixes. Known limitations at this release, with the step that changes each where one exists: OpenCode's package store is writable (step 7); concurrent launches share `state/rules.json` (step 9); a symlinked project config name has its target protected only when OpenCode starts from that project in a terminal; anything in an ALLOW folder can be changed or deleted, including git hooks and build scripts that run later outside the guard; reads are broad unless denied.
- `.github/CODEOWNERS` contains `* @ebrindley`, with a comment that external pull requests are not accepted.
- `.github/ISSUE_TEMPLATE/config.yml` keeps blank issues enabled (feature requests and the no-detail security fallback need a form that asks for nothing) and links to the advisory form.
- `.github/ISSUE_TEMPLATE/bug_report.yml` asks for the fields in the `CONTRIBUTING.md` guidance, warns to redact credentials and private paths, and sends bypasses to the advisory form.
- No tracked file names a person, hostname, employer or `/Users/<name>` path.

Release:
- The tag points at a commit where the golden test, the integration checks through the engine adapter and the step 5 migration tests pass.
- The release has the archive and checksum assets. The one-liner in `README.md` installs that release, not a local checkout.
- The release notes state: OpenCode only; an existing OpenCode Guard install is migrated; the renamed identifiers from step 3 (bypass variable, status tool, list path `~/Agent Guard/Guard List.txt`), so scripts using `OPENCODE_GUARD_BYPASS` need changing; the known limitations; where recovery is documented.

Each Mac, after the switch:
- In a terminal opened after the switch, `opencode` resolves to Agent Guard's shim and starts guarded. The status tool reports active; a write outside ALLOW is refused; creating `opencode.json` in the project is denied.
- In a terminal opened before the switch, `opencode` runs through the write-protected forwarder at OpenCode Guard's old command path and starts guarded (docs/DESIGN.md section 10, rule 7).
- Agent Guard's app starts OpenCode guarded. OpenCode Guard's app, and a Dock item that pointed at it, no longer start OpenCode unguarded.
- When OpenCode.app is opened directly, the plugin refuses tools with the relaunch message.
- `agent-guard doctor` passes.
- `~/.config/opencode/plugins` holds Agent Guard's plugin and not `opencode-guard.js`. No `# >>> opencode-guard >>>` block remains in `.zprofile`, `.zshrc` or `.bash_profile`; Agent Guard's block is in each of those files that exists.
- `~/Agent Guard/Guard List.txt` has the entries of the old list. OpenCode config `permission` values equal their pre-switch values. Agent Guard's permission record holds OpenCode Guard's recorded `orig` values, not the allow values OpenCode Guard wrote (docs/DESIGN.md section 10, rule 3). The switch time is recorded for forwarder removal.
- Recovery: rerunning the one-liner leaves a working install and changes no list, permission or record. The recovery data step 5 keeps is present, and the recovery procedure in docs/DESIGN.md section 10 matches the installed layout.
- Installed files carry no `com.apple.quarantine` attribute, and no Gatekeeper prompt appears. The result is recorded, since docs/DESIGN.md section 6 lists it as unverified on these Macs.

Order:
- When any check fails on the home Mac, the work Mac is not switched. The fix ships as a new release and the home Mac checks run again.
- When Santa on the work Mac would block Agent Guard's app, the work Mac switch waits until the app is admitted. The work Mac's admission route is recorded for step 8.
- When a check fails on the work Mac, it is restored with the section 10 recovery procedure and the failure is recorded here.

## How to Verify

- History:
  - Fetch PR refs: `git fetch origin '+refs/pull/*/head:refs/remotes/origin/pr/*'`.
  - Identities: `git log --all --format='%an %ae %cn %ce' | sort -u`.
  - Paths: `git grep -n -I -E '/Users/|/private/(tmp|var)' $(git rev-list --all)`; the only expected hits are the `dscl` lookup, the `/private/tmp` profile grants and the known historical scratch paths.
  - Every path ever tracked: `git log --all --name-only --format= | sort -u`.
  - PR text: `gh pr view 1 --comments` and `gh pr view 2 --comments`.
- Settings:
  - `gh api repos/ebrindley/AgentGuard --jq .visibility` prints `public`.
  - `gh api repos/ebrindley/AgentGuard/private-vulnerability-reporting` returns `"enabled": true`.
  - The Settings page shows "Collaborators only" under Pull requests.
- Release: `gh release view <tag>` lists the archive and checksum. `shasum -a 256` of the downloaded archive matches the checksum file.
- Each Mac:
  - `type -a opencode` in a new and in an already-open terminal.
  - Ask OpenCode to call the status tool, then to write one file outside ALLOW and to create `opencode.json` in the project.
  - `agent-guard doctor`.
  - `ls ~/.config/opencode/plugins`.
  - `grep -n '>>> ' ~/.zprofile ~/.zshrc ~/.bash_profile`.
  - Compare `jq .permission` output of each OpenCode config with the pre-switch copy, and the imported record with OpenCode Guard's `state/permissions.json`.
  - Rerun the one-liner and diff the list, configs and records.
  - `xattr -l` on the installed engine files and the app.
  - Work Mac: `santactl status`, and the app launch.
