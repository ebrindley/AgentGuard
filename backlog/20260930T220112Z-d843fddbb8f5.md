# Publish the first public release

## Description

Make the repository public with its contribution and security policy, and publish the first release (OpenCode only) with an installer that migrates an existing OpenCode Guard install.

## Scope / Surfaces Affected

- History review of every ref and pull request on GitHub before the visibility change, with the decision recorded.
- Public files: `CONTRIBUTING.md`, `SECURITY.md`, `.github/CODEOWNERS`, `.github/ISSUE_TEMPLATE/config.yml`, `.github/ISSUE_TEMPLATE/bug_report.yml`, and the `README.md` install, update, uninstall, recovery and limitations text.
- GitHub settings: pull requests limited to collaborators, public visibility, private vulnerability reporting.
- The first tag and GitHub release: archive, checksum, `install.sh` and release notes.
- Out of scope: switching particular machines to the release, Pi, the Rust launcher, and signing or notarization.

## Acceptance Criteria

- The history review's decision is recorded before the visibility change. Decision: published as is, 2026-10-01.
- The repository is public, pull requests are limited to collaborators, and private vulnerability reporting is enabled.
- `CONTRIBUTING.md` and `SECURITY.md` state the contribution policy, the private reporting channel and the known limitations at the release.
- No tracked file names a person, hostname, employer or `/Users/<name>` path.
- The release has the archive, checksum and `install.sh` assets, and the `README.md` one-liner installs the published release.
- Release notes state OpenCode only, the OpenCode Guard migration, the renamed identifiers and the known limitations.

## How to Verify

- `gh api repos/ebrindley/AgentGuard --jq .visibility` prints `public`.
- `gh api repos/ebrindley/AgentGuard/private-vulnerability-reporting` returns `"enabled": true`.
- `gh release view v0.1.0` lists the archive and checksum, and `shasum -a 256` of the downloaded archive matches the checksum file.
