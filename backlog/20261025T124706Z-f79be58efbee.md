# Remove ended OpenCode session folders

## Description

Every launch creates `$engine/state/opencode/<release>.XXXXXXXX` (`engine/launch:415`), and only staged checks remove theirs. On the development Mac on 2026-10-24 there were 16,614 such folders (259 MB), accumulating at about 900 a day. Almost all came from `opencode` CLI invocations, including `--version`; 6 came from desktop launches. Refused gui launches and `profile` mode also leave a folder behind.

## Scope / Surfaces Affected

- `engine/launch` and any engine helper it sources.
- Launcher tests (`test/opencode-runtime.mjs` or `test/test.sh`).
- `docs/OPERATIONS.md` or `docs/DESIGN.md`, where state folders are described.
- Out of scope:
  - the Rust launcher item `20260930T220116Z-77869d0e9dd5`;
  - the checker snapshot format and the plugin.

## Acceptance Criteria

- Each new session folder records its owning launch process (pid and start time) before the harness starts.
- Removal applies only to:
  - folders whose recorded owner is no longer running (the pid is gone, or its start time differs);
  - folders with no owner record whose modification time predates the last boot.
- Removal runs outside the sandbox, at most once per 24 hours per engine, using a stamp file. It never blocks or fails a launch, and never removes the current session or `state/opencode` itself.
- Refused gui launches, and modes that do not run a harness (`check`, `profile`), leave no folder.

## How to Verify

- Tests with disposable engine state cover:
  - a folder with a live owner is kept;
  - a folder with a dead owner is removed;
  - a reused pid with a different start time is removed;
  - an owner-less folder older than the last boot is removed;
  - an owner-less folder newer than the last boot is kept;
  - the stamp limits removal to once per 24 hours;
  - a refused launch leaves no folder.
- The hosted `tests` check passes.
