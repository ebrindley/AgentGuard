# Request cc-safety-net changes for Agent Guard's single checker

## Description

## Description

Requests to cc-safety-net (github.com/kenryu42/cc-safety-net) that Agent Guard's single checker would use. Agent Guard does not depend on any of them; each one lets an interim rule go.

## Scope / Surfaces Affected

- Recursive deletes without the force flag (`-r`, `-R`, `--recursive` alone) get the same scope checks as with it. In 2.4.14 such a delete of `../other` or `~/Documents` is allowed at every level.
- The Pi entry and `checkCommand` report a structured rule ID and every rule a command matched, not only the first.
- A user-level setting that ignores a project `.cc-safety-net/policy.json` that loosens built-in rules.
- `find ... -delete` scoped like recursive deletes, allowed below the working folder.
- `caffeinate` treated as a transparent wrapper.
