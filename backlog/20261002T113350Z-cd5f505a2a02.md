# Split the installer into modules with an action registry

## Description

docs/DESIGN.md section 6, Planned: installer structure, moved ahead of the Rust launcher so the Pi profile can be installed as switch actions with undo and recovery. `profiles/opencode/install.sh` (1,952 lines) becomes `installer/lib.zsh`, `installer/actions.zsh`, `installer/harness/opencode.zsh` and `installer/migrate/opencode-guard.zsh`.

## Scope / Surfaces Affected

- `installer/` modules; `profiles/opencode/install.sh` and `uninstall.sh` entry points; `engine/agent-guard`; `scripts/release.sh`, `scripts/bootstrap.zsh`, `scripts/check-seams.zsh` as needed; tests.
- Action registry: one ordered list of switch actions with phase, do and undo; `ag_switch`, `ag_rollback` and `ag_switch_begun` derive from it.
- Frozen recovery bundle: the transaction copies every module its undo handlers need.
- Candidate inventory: `plan.json` names the harnesses; the stamp gains `harnesses`.
- Sequential migrations: `state/migration.json` becomes a list of `{from, switched_at, retired}` records, read compatibly from the 0.1.x object form.
- `doctor`, `update` and `uninstall` iterate over the harnesses.
- `update` completes a pending migration or a newly found harness when the latest tag equals the installed one.
- Out of scope: Pi actions (Pi install item).

## Acceptance Criteria

- `test/install.sh`, `test/migrate.sh`, `test/bootstrap.sh`, `test/release.sh` and `test/test.sh` pass with no change to what they assert.
- A journal whose only begun action is a registered action outside the old fixed pattern is recognized as a begun switch and rolled back.
- Recovery succeeds when the new release folder is missing, using only the transaction's copies.
- An install from 0.1.1 with a migration record in object form updates and keeps its record.

## How to Verify

- Run the five suites outside any agent sandbox.
- New cases for the registry-derived recovery and the frozen bundle.
