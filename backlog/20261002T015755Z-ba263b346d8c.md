# Decide whether sessions can reach the SSH agent socket

## Description

The credential set removes `SSH_AUTH_SOCK` and `GPG_AGENT_INFO` from every session and denies `~/.ssh` (docs/DESIGN.md section 3, Credentials), but the SSH agent's socket stays reachable. macOS's own agent listens on a socket in a per-login folder under `/private/tmp` (`com.apple.launchd.<id>/Listeners` by default), which sessions can list, and the profile denies file writes, not socket connections. A process that finds the socket can set `SSH_AUTH_SOCK` itself and have the agent authenticate with every loaded key, for example to push over SSH. Denying the connection in SBPL is untested.

Find whether SBPL can deny connecting to the agent's socket without breaking other Unix sockets that sessions use, then deny it or accept the residual risk in writing.

## Scope / Surfaces Affected

- The final deny block (docs/DESIGN.md section 3, Rule order) and the conformance suite (section 8).
- The sockets in question: macOS's agent socket under `/private/tmp`; a third-party agent socket set through `IdentityAgent`; the GPG agent's socket in `~/.gnupg`, where the tool-credential file denies may or may not stop a connection.
- docs/DESIGN.md section 3, Credentials, and section 15.
- Out of scope: credentials in environment variables, the Keychain and 1Password, which stay usable inside a session by design.

## Acceptance Criteria

- A test under the real `sandbox-exec` records whether a candidate rule stops a connection to the agent's socket. The rule matches the socket by pattern, because the launchd folder name changes at each login.
- With the rule in place, a Unix socket created in the project or in temp still accepts connections, host name resolution still works, and the harnesses' own sockets (for example under OMP's `ssh-control`) still work.
- The test records whether the `~/.gnupg` denies already stop a connection to the GPG agent's socket.
- docs/DESIGN.md section 3, Credentials, records the decision in place of the "untested" note: the deny, with a conformance case, or the accepted risk with its reason.

## How to Verify

- With the agent running and a key loaded, inside a guarded session: `SSH_AUTH_SOCK=<found socket> ssh-add -l` fails with the rule and lists the key without it.
- The other socket cases pass with the rule.
