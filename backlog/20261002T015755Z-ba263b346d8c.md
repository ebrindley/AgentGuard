# Deny the SSH agent socket in sessions

## Description

Sessions cannot read `~/.ssh` and run without `SSH_AUTH_SOCK`, but macOS's ssh-agent listens on a socket in a per-login folder under `/private/tmp` (`com.apple.launchd.<id>/Listeners`), which sessions can list. A process that finds it can set `SSH_AUTH_SOCK` itself and authenticate with every loaded key, for example to push over SSH where the checker does not see the command. Deny the connection where Seatbelt can express it, with a documented setting for operators who use SSH inside sessions (docs/DESIGN.md decision D15).

## Scope / Surfaces Affected

- The Pi, OMP and Grok profiles, and OpenCode's with its credentials release (20261002T015753Z-acbfd918e9f9).
- The sockets: macOS's agent socket under `/private/tmp`; a third-party agent socket set through `IdentityAgent`; the GPG agent's socket in `~/.gnupg`.
- A Guard List or environment setting that leaves the agent reachable.
- docs/DESIGN.md section 3, Credentials, SECURITY.md and USAGE.md.
- Out of scope: credentials in environment variables, the keychain and 1Password, which stay usable inside a session by design.

## Acceptance Criteria

- A test under the real `sandbox-exec` records whether a rule stops a connection to the agent's socket. The rule matches the socket by pattern, because the launchd folder name changes at each login.
- With the rule in place, a Unix socket created in the project or in temp still accepts connections, host name resolution works, and the harnesses' own sockets (for example OMP's `ssh-control`) still work.
- The test records whether the `~/.gnupg` denies already stop a connection to the GPG agent's socket.
- With the setting, the agent is reachable again.
- If no rule can express the deny, SECURITY.md keeps the limitation and decision D15 records why.

## How to Verify

- With the agent running and a key loaded, inside a guarded session: `SSH_AUTH_SOCK=<found socket> ssh-add -l` fails with the rule and lists the key without it, or with the setting.
