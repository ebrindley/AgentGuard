# Assess Codex app-server daemon reach from peers

## Description

Since 0.157.0, Codex starts its app-server daemon automatically for eligible interactive sessions (openai/codex#47179). Its documentation places `thread/shellCommand` and `process/spawn` outside Codex's sandbox. Codex peers get `--no-daemon`, but a daemon started outside the session can still be running. Determine whether an ordinary Codex command in a guarded session reaches such a daemon and runs work outside the parent profile.

## Scope / Surfaces Affected

- Assessment only. `engine/peers.zsh`, `engine/peer-runtime.sb` and `SECURITY.md` change only if a recorded failure admits a change.

## Acceptance Criteria

- A recorded result for the current Codex version: whether the route is reachable from a guarded session, and what stops it if not.

## How to Verify

- Disposable `CODEX_HOME`, a daemon started outside the guard, an ordinary Codex command from a guarded shell, no copied credentials.
