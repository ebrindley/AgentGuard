# Leave permission keys without a recorded wrote value at uninstall

## Description

## Description

An OpenCode Guard install interrupted after it records `orig` and before it records `wrote` leaves record entries without `wrote`. The migration imports them unchanged.

At uninstall and at rollback, `ag_perm_restore` compares each config value with `wrote`. A missing `wrote` reads as null, so a key the user deleted after the import matches it and gets its `orig` value back. For example, a `bash` key with `orig` `{"*": "ask"}` that the user deleted comes back at uninstall.

Fix: restore only the keys whose entry has `wrote`, and release the fix as 0.1.1. The import already reports such entries as left as is.

## Scope / Surfaces Affected

- `profiles/opencode/install.sh`, `ag_perm_restore`: a key whose entry has no `wrote` is left as is.
- `test/install.sh`: one case. A record entry has no `wrote` and the user has deleted the key; after uninstall the key is still absent. The case fails without the fix.
- `docs/DESIGN.md`: the rule for restoring permission values.
- `README.md` and `SECURITY.md`: mentions of the current release name 0.1.1.
- Release v0.1.1: tag, assets and notes.

## Acceptance Criteria
