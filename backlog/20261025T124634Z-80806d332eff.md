# Explain desktop recovery under the guard

## Description

Under the guard, OpenCode Desktop shows behavior that users read as faults:

- Closing the last window leaves OpenCode running, as is usual on macOS. Opening Agent Guard again then shows "OpenCode is already running. Quit it, then open Agent Guard." The message does not say how to get the window back.
- The desktop updater cannot replace the app inside the guard. Observed with 2.1.1 staging 2.1.4 on 2026-10-24: an administrator prompt appeared, and the cancel was logged as `OSStatus error -60006`.
- Links and provider sign-in pages do not open, because `lsopen` is denied. OpenCode drops the failure: the click does nothing, and `window.log` records "failed to open external target".
- On 2026-10-24, with 2.1.4, a microphone prompt named "Agent Guard" appeared 155 ms after an agent reply finished, when OpenCode plays its default completion sound. OpenCode's helpers carry the `com.apple.security.device.audio-input` entitlement.

Users need recovery steps. The boundary does not change.

## Scope / Surfaces Affected

- `engine/launch`: the already-running refusal in gui mode.
- `docs/USAGE.md`: the desktop section.
- `docs/DESIGN.md` and `SECURITY.md`, where they quote the message or list desktop limitations.
- Tests that assert the message, if any.
- Out of scope:
  - changing the already-running check, or reopening windows automatically;
  - profile rules;
  - fixtures under `test/fixtures`.

## Acceptance Criteria

- The refusal says how to show the window of an OpenCode opened from Agent Guard, through its Dock icon, and what to do when OpenCode was opened outside Agent Guard.
- `docs/USAGE.md` documents:
  - the difference between closing the window and quitting;
  - updating OpenCode outside the guard, then reopening it through Agent Guard;
  - links and sign-in pages that do not open, with a workaround verified from OpenCode's code or behavior;
  - the microphone prompt, what triggers it and the user's options.
- Each documented behavior names the version it was observed with, or is marked as an inference.

## How to Verify

- Existing tests that check launcher messages cover the new text.
- The hosted `tests` check passes.
