# Write-deny Pi's agent bin and tools folders

## Description

## Scope / Surfaces Affected
Pi 1.3.0 puts `bin/` in its active agent directory first on the PATH of every Bash command and prefers its `rg` and `fd` there; at startup it moves legacy `tools/{fd,rg}` into `bin/`. Write-deny both folders in Pi sessions, as OpenCode's `~/.cache/opencode/bin` is denied. Record in docs/DESIGN.md that `models-store.json` stays writable: Pi rewrites it on catalog refresh, and a session can already read Pi's credentials and reach the network, so a changed endpoint adds no new exposure. Surfaces: profiles/pi/sandbox/pi-sandbox.sb, its probe script, the Pi golden difference record and patch, docs/DESIGN.md, SECURITY.md. Out of scope: linked state-root config files, other review items.

## Acceptance Criteria
When a guarded Pi session creates or modifies a file under `bin/` or `tools/` in its active agent directory, the write is denied, at the default and a relocated root. Pi runtime state such as sessions and themes stays writable. When `rg` or `fd` is missing, Pi warns that the download failed and continues.

## How to Verify
The Pi profile probe script must pass, and must fail on the new markers when the denies are removed. test/pi-files.mjs must pass with the change recorded as a difference.
