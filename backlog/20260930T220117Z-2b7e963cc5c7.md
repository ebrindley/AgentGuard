# Add @project for OpenCode

## Description

`@project` lets a Guard List entry name the folder a session was started for, so one list grants each session its own project instead of a fixed folder (docs/DESIGN.md section 4). Built for OpenCode on the zsh engine (section 12, step 10a; decision D12). The installer split this item also carried shipped as step 7a (d1a54f2, #21). Pi and OMP's move onto a shared engine is not built (D12).

## Scope / Surfaces Affected

- The list parser and launcher: `@project` resolution and its refusal rules (docs/DESIGN.md section 4).
- OpenCode's positional project argument (`opencode [project]`) and what the app launcher means by it.
- Guard List template: `@project` added commented out.
- Each launch's rules file (20260930T220116Z-77869d0e9dd5), so concurrent launches in different projects keep their own rules.
- Out of scope: Pi and OMP, the protection union and composition (D12).

## Acceptance Criteria

- `opencode [project]` and a launch from inside a project resolve `@project` to that folder, after link resolution.
- A `@project` that is too broad, sensitive or contains the engine folder refuses the launch with a message, and the refusal is logged.
- A protected name in `@project` that is a symlink is handled as section 4 describes.
- Two concurrent launches in different projects each write only their own project.
- The app launcher's `@project` is defined after measuring its working directory.
- New lists get `@project` commented out; existing lists are unchanged.

## How to Verify

- Disposable-home tests for each case above, under the real `sandbox-exec`.
- `node test/golden.mjs` passes, with any profile change recorded as a difference.
