# Apply the D13 checker policy to OpenCode

## Description

OpenCode's checker denies routine Git work such as `git restore <file>`, `git checkout -- <file>`, `git stash drop` and `git branch -D`, and allows setting `core.hooksPath`. Apply decision D13 (docs/DESIGN.md section 15) to OpenCode's per-session checker copy, and move the copy builder into engine code that Pi and OMP will share.

## Scope / Surfaces Affected

- `profiles/opencode/skills.zsh` `opencode_checker_snapshot` and `engine/launch`: the builder moves to an engine library; the copy switches off D13's ten built-in rules unless the user's policy names them, and adds the release-owned `agent-guard-git` rulebook.
- `engine/` templates: the `agent-guard-git` rulebook (version 2): whole-tree `git restore` and `git checkout`, and `core.hooksPath` writes.
- OpenCode plugin health: a policy state other than `ready` or a missing `agent-guard-git` rulebook blocks the call.
- docs/USAGE.md and SECURITY.md: what OpenCode sessions now allow and deny.
- Out of scope: Pi and OMP (separate item); changes to `~/.cc-safety-net`.

## Acceptance Criteria

- OpenCode sessions allow path-scoped `git restore` and `git checkout -- <path>`, `git stash drop`, `git branch -D`, `git tag -d`, `git merge --abort`, `git rebase --abort` and `git push --delete`.
- They deny whole-tree `git restore` and `git checkout`, and `git config` setting `core.hooksPath`, while `git config --get core.hooksPath` stays allowed.
- A rule the user's own policy names keeps the user's setting.
- `~/.cc-safety-net` is unchanged by install, launch and update.

## How to Verify

- Checker tests against the session copy in a disposable home for each allowed and denied command above.
- `node test/golden.mjs` and `zsh test/test.sh`.
