# Correct misleading guard messages

## Description

## Scope / Surfaces Affected

Six separately landed changes that bring printed guidance and list handling in
line with the running guard:

1. The README table, the Guard List template and `last-launch-opencode.log`
   state OpenCode's fixed credential-path and `.env` denies; the template's
   `@project` comment describes the desktop app's behavior.
2. `ALLOW`, `READ ONLY` and `DENY` headings accept a `# comment` suffix in the
   launcher, the migration preview and the installer's project insertion.
3. The checker's session copy keeps `rm.recursive-force-dynamic-target` on
   when `policy.json` is malformed, and the warning names what was not applied.
4. A launch refused before its log header is written is recorded as its own
   entry with its reason; OpenCode 2 server startup failures name `server.log`.
5. Refusals name a remedy that works: a READ ONLY entry, a set `PI_EXECUTABLE`
   or `OMP_EXECUTABLE`, the recorded Grok executable, and the log line that
   explains missing sign-in commands.
6. USAGE.md, SECURITY.md and SKILLS.md name the stable release, and the known
   limitations link resolves.

## Acceptance Criteria

- [ ] Each change lands as its own pull request with the hosted `tests` check passing.
- [ ] No profile rule, grant or checker verdict changes except that a malformed
      `policy.json` no longer drops the dynamic-delete rule.
- [ ] Existing Guard Lists, including the template's introductory lines, parse as before.

  `test/opencode-runtime.mjs`, `test/pi-launch.mjs`, `test/pi-files.mjs`, `test/golden.mjs`.
