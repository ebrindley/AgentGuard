# Run MCP sign-in alongside guarded Desktop

## Description

## Scope / Surfaces Affected

`profiles/opencode/runtime.zsh` routes OpenCode 2 `mcp auth` and `mcp logout`
to a launcher-owned service, and that launch is refused while another service
is running. Read from the source, signing in to an MCP server from a guarded
terminal should therefore be refused while guarded Desktop is open. This has
not been reproduced.

`mcp add`, `plugin add` and `plugin remove` already run without a service, and
`auth` subcommands already run with `--standalone`. If the refusal reproduces,
route `mcp auth` and `mcp logout` the same way as `auth`, and update the command
table in `docs/USAGE.md`.

## Acceptance Criteria

- [ ] The refusal is reproduced with guarded Desktop open, or the item is closed as not reproducible.
- [ ] Given guarded Desktop is open, when `opencode mcp auth NAME` runs in a guarded terminal, then it starts under the existing sandbox without stopping or adopting the Desktop service.
- [ ] Other `mcp` subcommands keep their current routing, and no filesystem grant or deny changes.

## How to Verify

- `node test/opencode-runtime.mjs` must pass with a case for the two subcommands.
- `node test/opencode-v2-native.mjs routing` must pass outside a sandbox.
