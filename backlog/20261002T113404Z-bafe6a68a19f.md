# Install and migrate Pi and OMP through the Agent Guard installer

## Description

The installer actions that put the adopted Pi profile in place, migrate a pi-sandbox-guard install, update it and uninstall it, and the OpenCode-session protection of Pi's files.

## Scope / Surfaces Affected

- `installer/harness/pi.zsh` and `installer/migrate/pi-sandbox-guard.zsh`: switch actions with backup and undo for `~/.local/bin/{pi,omp,pi-sandbox.sb,pi-sandbox-preamble.zsh}`, the extension folder `~/.pi/agent/extensions/pi-sandbox-guard/` and `$engine/bin/{pi,omp}`; detection; refusal while Pi or OMP runs, matched by argv; staged checks; gate; legacy bundle with the security log left in place; fresh-install checker Node; backup and report of a non-guard `~/.local/bin/pi` or `omp`; uninstall of the Pi pieces with the legacy bundle copied to `~/Agent Guard/`.
- `update` completes a pending Pi migration at the same version; a Mac with both old guards migrates in one command.
- OpenCode sessions write-deny Pi's guard files when the stamp lists Pi.
- `test/migrate-pi.sh`.
- Out of scope: Pi policy (Pi profile item).

## Acceptance Criteria

- Migration from a real 7ad441f install passes with failures and kills at every switch point, reruns and uninstall.
- Both old guards on one Mac migrate in one command.
- An OpenCode session with Pi installed cannot write the Pi launchers, wrappers, extension or bindings, even under an ALLOW entry.

## How to Verify

- `test/migrate-pi.sh` and the extended installer tests outside any agent sandbox.

## Dependencies

- Split the installer into modules.
- Adopt pi-sandbox-guard's Pi profile.
- Add agent-guard bind, wrapper and Pi doctor checks.
