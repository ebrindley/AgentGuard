# Resolve Guard List entries independently of session-writable state

## Description

A Guard List entry resolved to a different path depending on filesystem state a
guarded session could write, so a session could disarm an operator's DENY or
READ ONLY entry, or re-aim an ALLOW grant, for the next launch.

Two routes, one cause. `normalize` removed Finder backslash escapes only when
the escaped string did not already exist, so creating a name containing a
literal backslash made the escaped entry resolve to that name instead of the
intended path. Separately, an entry resolved its whole symlink chain in one
`:P` step and the links themselves received no rule, so replacing any of them
re-aimed the entry and left the intended target with no rule at all.

Entry resolution now ignores the disk for escaping: a quoted entry is literal,
an unquoted entry has its escapes removed. The walk follows one link at a time
and records every link on the way, including links inside the chain, which are
then pinned against replacement. A dangling link keeps its own name and is not
followed, as the rules for a missing target require. A chain longer than 32
hops stops at the link reached, so a cycle cannot drop the entry's rule.

## Scope / Surfaces Affected

`engine/launch`: the Guard List parser (`normalize`) and the pinned-path set
rendered as literal write denies. No change to profile data, the plugin, the
installer or Pi's guard.

## Non-goals

- Not changing the Guard List file format or its headings.
- Not protecting files inside ALLOW folders.
- Not addressing other list semantics such as Unicode normalization.

## Acceptance Criteria

- [ ] An unquoted entry's Finder escapes must be removed whether or not a path
      containing a literal backslash exists.
- [ ] A quoted entry must be taken literally.
- [ ] Every symlink an entry resolves through, including one inside the chain
      and one reached through a writable grant, must be write-denied so a
      session cannot replace it and re-aim the entry.
- [ ] A DENY entry's target must stay denied after a session attempts to
      replace a link on the way to it.
- [ ] Resolution must match the previous behaviour for relative links, dangling
      links, `..` after a link, and symlink cycles.
- [ ] Ordinary writes inside ALLOW, including through a link an entry names,
      must still be permitted.
- [ ] `node test/golden.mjs` must report the recorded profiles unchanged and
      its symlink and missing-target case passing.

## How to Verify

```bash
node test/golden.mjs
zsh test/test.sh
```

Golden should pass all six checks. `test/test.sh` requires a real OpenCode CLI
ahead of the Guard shim on PATH, or `AG_TEST_OPENCODE` naming one; without it
its post-switch gate fails for reasons unrelated to this change, so compare a
run against one from an unmodified checkout via `--source`.
