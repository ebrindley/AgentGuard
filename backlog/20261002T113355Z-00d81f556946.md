# Adopt pi-sandbox-guard's Pi profile with Agent Guard's protections

## Description

Vendor pi-sandbox-guard 7ad441f's launcher, preamble, Seatbelt profile and extension into `profiles/pi/` and apply the recorded differences that the adopted plan requires for Pi sessions.

## Scope / Surfaces Affected

- `profiles/pi/`: pi-sandbox-guard's `launchers/`, `sandbox/`, `src/`, the extension entry and the test scripts, in pi-sandbox-guard's relative layout.
- Recorded differences, each with a test:
  1. Agent Guard's base write protections: the engine folder, `~/Agent Guard`, `~/Applications/Agent Guard.app`, OpenCode Guard's engine folder, `~/.config/opencode`, `~/.opencode`, `~/.cc-safety-net` except `logs`, `~/Library/LaunchAgents`, the eight shell startup files, and the resolved targets of any of these that are symlinks, passed as parameters.
  2. Project refusals for those folders.
  3. Decision D7's denies: `lsopen`, `job-creation`, and exec of `open`, `osascript`, `osacompile`, `codesign`, `diskutil`, `launchctl`, `sudo`.
  4. Step 7's denies for OpenCode's package stores, `bin` and model catalog at the default and the environment's cache root.
  5. `npm run bind` becomes `agent-guard bind` in messages.
- pi-sandbox-guard's suites vendored and run in CI; `test-ops.sh` retired.
- Out of scope: installation, commands, OpenCode's profile.

## Acceptance Criteria

- A file comparison against 7ad441f allows only the recorded differences.
- pi-sandbox-guard's suites pass, changed only where a recorded difference changes what they assert.
- Each difference has a passing test, including a Pi session whose project is `~/Agent Guard` being refused and a symlinked `~/.zshrc` whose target is in the project being write-denied.
- Nested-launch tests assert the real behavior in both directions.

## How to Verify

- Run the vendored suites and the new cases outside any agent sandbox.

## Dependencies

- Step 7's path set (Protect OpenCode's package store item) for difference 4.
